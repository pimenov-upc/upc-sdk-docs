Пакет `@upc/xml-utils` надає функції для розбору XML, перетворення XML у
JSON-сумісні об’єкти, формування XML-запитів UPC.

## Швидкий приклад

```ts
import { createXmlOperation, xml2json } from '@upc/xml-utils';

const xml = createXmlOperation('LookupRequest', {
  MerchantId: 'merchant-123',
  Lookup: {
    Code: 'A&B'
  }
});

const json = xml2json(xml);

console.log(xml);
console.log(json);
```

Функція екранує спеціальні символи текстових значень, тому `A&B` у створеному
XML стане `A&amp;B`. Результат `xml2json` має тип `JsonObject`.

## Публічний API

| Експорт | Призначення |
|---|---|
| `XmlValue`, `XmlObject` | Типи значень та об’єктів для структури XML. |
| `JsonValue`, `JsonObject` | Типи значень та об’єктів для JSON-сумісного результату. |
| `str2xml(xml)` | Розбирає XML-рядок у структуру `XmlObject`. |
| `xml2json(xml)` | Перетворює XML-рядок у JSON-сумісний `JsonObject`. |
| `createXmlOperation(operation, payload)` | Формує XML-документ, у якому `operation` є кореневим елементом. |
| `createXmlRequest(operation, messageId, payload)` | Формує XML-запит UPC у конверті `ECommerceConnect` та `Message`. |

## Типи даних

- `XmlValue` — це рядок
- `XmlObject` об’єкт або масив інших `XmlValue`. 

`XmlObject` є об’єктом, ключі якого відповідають іменам XML-елементів. 

Для JSON застосовуються аналогічні типи `JsonValue` і `JsonObject`.

Наприклад, так можна описати вкладений запит:

```ts
const payload = {
  MerchantId: 'merchant-123',
  Transaction: {
    Amount: '125.00'
  }
};
```

Тип `XmlNode` також оголошений усередині пакета, але не експортується з його
публічної точки входу.

## Розбір XML

### `str2xml(xml)`

Повертає об’єкт, у якому кореневий XML-елемент є властивістю верхнього рівня.
Текст елемента зберігається у властивості `#text`. Якщо всередині елемента є
інші елементи, текст додається до того самого об’єкта.

Повторювані елементи перетворюються на масиви. Наприклад, фрагмент
`<Reply><Code>OK</Code><Code>RETRY</Code></Reply>` дає структуру на кшталт:

```ts
{
  Reply: {
    Code: [
      { '#text': 'OK' },
      { '#text': 'RETRY' }
    ]
  }
}
```

Парсер декодує стандартні XML-посилання `&amp;`, `&lt;`, `&gt;`, `&quot;`,
`&apos;` та числові посилання на символи. Він також приймає секції CDATA,
коментарі, інструкції обробки та `DOCTYPE`. Атрибути можуть бути присутні у
вхідному XML, але до повернутого об’єкта вони не додаються.

Невірний XML, непідтримуване посилання на сутність, відсутній кореневий елемент,
кілька кореневих елементів або незакритий тег призводять до `SyntaxError`.
Розбір не є повною реалізацією XML-стандарту; не покладайтеся на нього для
збереження атрибутів або всіх особливостей XML-документа.

### `xml2json(xml)`

Спершу розбирає XML, а потім спрощує структуру:

- елемент, що містить лише текст, стає рядком;
- порожній елемент стає порожнім рядком;
- вкладені елементи стають властивостями об’єкта;
- повторювані однойменні елементи залишаються масивом.

Наприклад, результат для `<Reply><Code>OK</Code><Empty/></Reply>` буде таким:

```ts
{
  Reply: {
    Code: 'OK',
    Empty: ''
  }
}
```

Обидві функції розбору приймають лише XML-рядок. Вони не перевіряють схему
повідомлення UPC і не перетворюють текстові значення на числа чи логічні типи.

## Формування XML

### `createXmlOperation(operation, payload)`

Створює XML-документ із XML-заголовком, де `operation` є кореневим елементом.
Ця функція не додає конверт UPC:

```ts
import { createXmlOperation } from '@upc/xml-utils';

const xml = createXmlOperation('LookupRequest', {
  MerchantId: 'merchant-123'
});
```

### `createXmlRequest(operation, messageId, payload)`

Створює запит UPC у конверті `ECommerceConnect`, додає елемент `Message` з
атрибутами `id` і `version="1.0"`, а всередині розміщує елемент `operation` та
поля `payload`.

```ts
import { createXmlRequest } from '@upc/xml-utils';

const xml = createXmlRequest('LookupRequest', 1, {
  MerchantId: 'merchant-123'
});
```

Обидві функції екранують текстові значення XML, включно з `&`, `<`, `>`, лапками
та апострофами. У вкладених об’єктах ключі з префіксом `@_` формують атрибути:

```ts
const xml = createXmlOperation('PaymentRequest', {
  Transaction: {
    '@_Id': 'AUTH',
    Amount: '125.00'
  }
});
```

Цей фрагмент створить атрибут `Id="AUTH"` у елемента `Transaction`. Назви
операції, ключі об’єктів і назви атрибутів використовуються як XML-імена та не
екрануються. Передавайте для них лише коректні, довірені назви. Не вставляйте
неперевірені дані користувача в ці позиції.

Попри те, що тип `XmlValue` дозволяє масиви, генератор не має окремої обробки
масивів як повторюваних XML-елементів. Не передавайте масиви до функцій
формування XML: їхні числові індекси можуть стати некоректними назвами тегів.
